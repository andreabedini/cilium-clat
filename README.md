# cilium-clat

A chained CNI plugin that gives every pod in an IPv6-only Cilium cluster a
working IPv4 stack, with a stateless eBPF CLAT (RFC 6877, RFC 7915) attached
to the pod side of the veth. No process per pod, no change to Cilium.

Design: [DESIGN.md](DESIGN.md). Review and deviations: [REVIEW.md](REVIEW.md).

## Layout

| Path | What |
| --- | --- |
| `bpf/clat.c` | `clat_egress` (IPv4 to IPv6) and `clat_ingress` (IPv6 to IPv4), plus a per-CPU counter map |
| `bpf/include/` | libbpf helper headers vendored from cilium/ebpf (LGPL-2.1 OR BSD-2-Clause) |
| `internal/clat/` | Config parsing, ADD/DEL/CHECK, netns setup, BPF load and attach, counters. `clat_bpfel.{go,o}` are generated by bpf2go and committed |
| `cmd/cilium-clat/` | The plugin binary, plus the `counters` subcommand |
| `deploy/` | Installer DaemonSet, `cni-configuration` ConfigMap, Cilium Helm values, Dockerfile |
| `hack/netns-test.sh` | Three-namespace integration test without Cilium or a NAT64 |

## Build and test

```sh
make build        # bin/cilium-clat, static
make test         # unit tests; BPF tests skip without CAP_BPF
make test-bpf     # as root: verifier + BPF_PROG_TEST_RUN packet oracle
make test-netns   # as root: pod/node/server namespaces, curl, ping, tracepath, UDP
make generate     # after editing bpf/clat.c (needs clang)
```

The BPF tests build packets in Go, run each program with
`BPF_PROG_TEST_RUN`, and check the output against an independently built
expected frame and RFC 1071 checksum arithmetic. Covered: TCP, UDP, UDP with
zero checksum, ICMP echo both ways, fragments both ways, IPv4 options,
extension headers, every ICMPv6 error type including the embedded header,
Packet Too Big with and without an inner Fragment header, pass-through of
native IPv6, DNS64 and NDP traffic, and a full round trip.

## Deploy

1. `kubectl apply -f deploy/cni-configuration.yaml`
2. Merge `deploy/cilium-values.yaml` into the Cilium Helm values and upgrade.
   Cilium writes the chained conflist to `/etc/cni/net.d`.
3. Build and push the image (`make image`), then
   `kubectl apply -f deploy/installer.yaml`.
4. Restart the workloads that need IPv4.

`excludeNamespaces` keeps namespaces that still run a CLAT sidecar out.

## Debugging

```sh
# counters in a pod netns (drops per reason, translated per direction)
cilium-clat counters --netns /proc/<pid>/ns/net
# the plugin log
tail -f /var/log/cilium-clat.log
```

Inside a pod: `ip -4 addr`, `ip -4 route` (default via 192.0.0.1, mtu = eth0 mtu
minus 20), `tc filter show dev eth0 egress` and `ingress` show `clat_egress`
and `clat_ingress` as direct-action bpf filters.

## Limits (phase 1)

- Fragmented ICMP is dropped in both directions: the ICMPv6 pseudo-header
  needs the whole datagram's length. Use TCP or UDP for fragment tests.
- ICMPv4 errors sent by the pod are dropped.
- ICMP errors from routers on the IPv6 path arrive with source `192.0.0.8`
  (RFC 7335), so `traceroute -4` shows that address for every IPv6 hop.
- `tracepath -4` cannot discover the path MTU: `IP_PMTUDISC_PROBE` ignores
  the route MTU. Use `ping -4 -M do` or TCP.
- veth datapath only.
- IPv4 multicast and broadcast are dropped.
